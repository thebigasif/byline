### Changed

- The server's idle memory sits under its budget again: freed pages return to the OS at once (`MIMALLOC_PURGE_DELAY=0`), set everywhere Khalid runs, in the deployment image, the systemd unit, `compose.yaml`, and named for hand-run servers in the install docs. The setting is recorded in the performance standard with its CI measurements, including the delays that were measured and rejected. The database's page-cache caps that an earlier revision of this change carried were removed again: they made the cold start re-read pages from disk (the migration and the first render read the file four times) for a memory ceiling the purge delay already meets.
