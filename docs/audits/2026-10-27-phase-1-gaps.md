# Phase 1 gap audit, 2026-10-27

What this is: every PRD requirement (`docs/PRD.md`) in Phase 1 scope, plus the Phase 2 linter and the Phase 3 theme work pulled forward, checked against the code and tests on `main` at `6a1c3a5`. Status lines in `docs/phases/phase-1.md` were not trusted; only code and tests count.

How to read it: **done** means the acceptance line holds on `main` and a test proves it. **Partial** means some of it is built and tested, usually inside a library crate, but the acceptance line does not hold. **Missing** means nothing on `main` does it. Each partial or missing row has a task brief below the tables. A brief names the work, not the track; the CTO assigns tracks.

Branches still open on `origin` were read but not counted. Where an open branch looks like it closes a gap, the brief names it so nobody builds it twice. Check the branch when it lands, because its title is all this audit read.

## Summary

- 64 rows: 8 done, 44 partial, 12 missing.
- The libraries are far ahead of the binary. `crates/khalid/Cargo.toml` does not depend on `khalid-api`, `khalid-webhooks`, `khalid-theme`, `khalid-mount`, `khalid-share-image` or `khalid-media`. So the Content API, Admin API, webhooks, theme sync, proxy rules, share images and image variants are tested only inside their own crates. Nobody can reach them through `khalid`.
- `khalid serve` and `khalid build` render pages differently. `build.rs` adds the SEO head through `build_seo::heads`. `site_pages.rs` (serve) does not, so served pages have no JSON-LD, no hreflang and no SEO head from `khalid-seo`. Serve also has no sitemap, `robots.txt`, `llms.txt` or feeds.
- `Config` holds only name, address, mount, mode, slugs and languages. `build_seo::site` therefore uses defaults for meta templates, index policy, share image, verification codes, crawler rules, feeds, link policy and publisher. A site owner can set none of them.
- No CI job runs a browser. Lighthouse, the W3C validator, axe, scripts-off checks and the six-width test do not exist, so KH-WEB-1 to KH-WEB-7 cannot be done until task 1.22 is built.

## Cross-cutting briefs

These five gaps sit under many rows. Building them closes more than any single row.

**X1. Served pages carry the same SEO head as built pages.** In `crates/khalid/src/site_pages.rs`, run the pages through `build_seo::heads` the way `build.rs` does, so `meta.seo_head` is set on every served page. Extend `crates/khalid/tests/serve.rs` to assert JSON-LD, canonical, hreflang with `x-default`, and Open Graph on every page type it fetches. No open branch covers this; `task/p1-perf-serve-once` still calls `heads` only in `build.rs`.

**X2. Serve and build emit every SEO file.** Add the sitemap index and sitemaps, `robots.txt`, `llms.txt`, root verification files, the three feeds per language and category, and the HTML sitemap page to both `khalid build` (`build_files.rs`) and `khalid serve` (pages with the XML, text and JSON media types). Test each address over HTTP in `serve.rs` and as a file in `build_files.rs`. `task/p1-seowire-feeds` adds feeds to build only.

**X3. SEO settings in `site.toml`.** Add typed sections to `Config` (`khalid-core`, its own small pull request) for meta templates, index policy per archive type, default share image, Twitter handle, verification codes, crawler allow and block lists, feed options, link policy with affiliate domains, and the publisher. Then feed them to `build_seo::site`. Each section needs a `fixtures/invalid/` folder for its mistake and a build snapshot that shows the setting applied.

**X4. `routes.toml` decides addresses.** `build_pages::path_of` builds `mount + lang + slug/` and ignores the routes file, which is only validated. Use `Routes::address` for every post. Build collection, tag, category, channel and glossary list pages where the routes put them, and turn `aliases` into 308 redirects in serve and redirect files in build through `khalid-seo`'s `RedirectTable`. Test with the URL cases from task 1.9 through `khalid serve`. `task/p1-seowire-redirects` and `task/p1-linkfix-glossary-pages` cover part of this.

**X5. The API inside the binary.** Make `khalid serve` mount the `khalid-api` router with SQLite stores: `ContentStore` over the content index, `PostStore` over the files, and `KeyStore` over `api_keys` with a `key_id` column (question in the phase brief). Add `khalid keys create` and `revoke`. Fire webhook events from publish and Admin writes, and start `DeliveryLog` and `retry_deliveries` in serve. The `task/p1-apiwire-*` stack (keys, cli, content, serve-content, drafts, post-text, publish, publish-files, serve-admin) covers most of this; this audit did not check its tests.

## Task briefs

**B-INS-5. Headless mode.** Add `theme = false` (or `mode = "headless"`, an ADR call) to `site.toml`. When it is set, `khalid serve` answers the API, feeds, sitemaps and redirects, and returns 404 for HTML pages, while `khalid build` writes no HTML. Test both with the demo site. The starter kits stay in Phase 7.

**B-CON-2. Collection intros on list pages.** Build a list page per collection at its routes address (X4) and pass the parsed `_index.md` body as `RenderListing.intro` instead of `None` in `build_pages.rs`. Add a demo `_index.md` and a serve test that finds its text on the collection page.

**B-CON-3. Images beside a folder post.** Copy each `Entry::assets` file to the built post's folder, serve it from the same address, and resolve relative image paths in the body to it. Feed those images through `khalid-media` for variants (B-WEB-5). Test: a demo folder post with an image answers 200 for the image, and changing the image changes the post's content hash and ETag.

**B-CON-5. Maths as a block.** Give display maths (`$$...$$`) a block kind in `khalid-content` with a round-trip test, and add it to the round-trip property generator. Inline maths can stay a render-time rule.

**B-CON-6. Wikilinks on real pages.** Build a `Wikilinks` table from the site content once and call `render_linked` in `build_pages::body_html`, so build, serve and feeds all link. Test: a demo glossary wikilink is an `a` element in both languages through `khalid serve`. `task/p1-linkfix-render` claims this; verify it when it lands.

**B-CON-8. hreflang on every served page.** Covered by X1. Also extend the test to page, author, list and glossary pages, not only post and home.

**B-CON-9. Routes in use, and overlapping collections.** Covered by X4 for addresses, channels and aliases. Add a lint warning, with a catalogue message and fixture, when two collections' filters could claim the same post.

**B-CON-10. A deleted database restored by serve.** Make `khalid serve` open `data/site.db`, rebuild the index on start when it is missing or out of date, and add a test that deletes the file, starts serve, and fetches every page type plus one Content API call.

**B-CON-11. Incremental re-render.** Track which pages depend on which file (post page, its lists, its author, its translations, feeds, sitemaps) and re-render only those on a change. **B-SEO-1. Meta templates and short lengths.** Settings via X3. Add lint warnings for a title or description that is too short, with fixtures. The snippet preview stays with the Phase 4 editor.

**B-SEO-2. The generated share image, used.** Add a content-hash cache to `khalid-share-image`, depend on it from the binary, and generate an image for any page with no `image` field.
